# flight-radar-maps

Downloadable map tiles for **[ESP32 Flight Radar](https://github.com/delphicchen/esp32_flight_radar)**.

The firmware used to bake one location into `map_data.h` at compile time, which meant a
prebuilt image only had a useful map in Taiwan. It now downloads the tiles covering its own
coordinates from this repository instead, so the same binary works anywhere.

Nothing here is hand-written: everything under `v1/` is generated by
[`tools/make_tiles.py`](https://github.com/delphicchen/esp32_flight_radar/blob/main/tools/make_tiles.py)
in the firmware repo. Don't edit tiles — regenerate them.

## Layout

```
v1/L2/N50E010.bin
 │  │  └─ cell, named by its south-west corner, 10° aligned (S/W for negatives)
 │  └──── detail level
 └─────── format version
```

**A missing tile is not an error.** Ocean cells are simply never written, and the firmware
treats `404` as "no map data here". That is why there is no index file to keep in sync.

### Detail levels

Tolerance follows the firmware's "about one radar pixel" rule, evaluated at the largest
radar range each level is meant to serve. The device picks the level matching its current
range setting.

| Level | Douglas-Peucker tolerance | Serves radar range |
|-------|---------------------------|--------------------|
| `L1`  | 0.0198° | > 250 km |
| `L2`  | 0.0079° | 100–250 km |
| `L3`  | 0.0020° | < 100 km |

## Tile format (v1, little-endian)

A 64-byte header, then five sections. Offsets in the table are relative to the start of the
payload (i.e. to byte 64).

```
offset  type      field
  0     char[4]   magic "FRMT"
  4     u16       format version (1)
  6     u16       flags — bit 0 = complete
  8     u32       crc32 of the payload
 12     f32       cell south-west latitude
 16     f32       cell south-west longitude
 20     u8        detail level
 21     u8        layers present, bitmask:
                    1 outline  2 airports  4 runways  8 fixes  16 airspaces
 22     u16       reserved
 24     u32[2]×5  (offset, length) for each of the five sections below
```

| Section | Record |
|---------|--------|
| `outline` | `f32 lat, f32 lon` pairs. A **NaN latitude starts a new polyline**, and that record's longitude slot carries the brightness class: `0` coastline, `1` country border, `2` state border. |
| `airports` | `char icao[5]`, `f32 lat`, `f32 lon` — 13 bytes |
| `runways` | `f32 lat1, lon1, lat2, lon2, xlat1, xlon1, xlat2, xlon2` — thresholds, then the extended centreline — 32 bytes |
| `fixes` | `char name[6]`, `f32 lat`, `f32 lon` — 14 bytes |
| `airspaces` | `u16 count`, `u16 strtab_len`, then `count` × `{u8 cls, u8 pad, u16 name_off, u16 npts, u16 pad}`, then the NUL-separated string table, then each record's `npts` × `f32 lat, lon` in record order. `cls`: 0 CTR, 1 TMA, 2 CTA, 3 other. |

The NaN-separator convention and the record layouts mirror the structures the firmware
already used in `map_data.h`, so the drawing code did not have to be rewritten around a new
shape.

## Sources and licences

Every source here is redistributable — that is the reason these tiles can be hosted at all.

| Layer | Source | Licence |
|-------|--------|---------|
| Coastline, country and state borders | [Natural Earth](https://www.naturalearthdata.com/) 1:10m | public domain |
| Airports, runways, navaids | [OurAirports](https://ourairports.com/) | public domain |
| Taiwan county outline | [g0v/twgeojson](https://github.com/g0v/twgeojson) | CC0 1.0 |
| Taiwan airspace (FIR, TMAs, control zones) | converted from [Taiwan CAA eAIP](https://ais.caa.gov.tw/) ENR 2.1 | our own conversion |

**[openAIP](https://www.openaip.net/) airspace is deliberately not included.** Its data is
CC BY-NC: fine for you to fetch with your own API key when regenerating a map for your own
build, not something this repository redistributes to everyone. If you want airspace outside
Taiwan, use `--openaip-key` with `make_map.py` and compile your own firmware, or convert your
country's eAIP the way the Taiwan pack was made.

## Regenerating

From a checkout of the firmware repo, with `tools/cache/` populated (the script downloads and
caches the sources on first run):

```bash
# one cell, to eyeball it
python tools/make_tiles.py --out ../flight-radar-maps --levels 2 --cells N50E010

# everything — roughly half an hour
python tools/make_tiles.py --out ../flight-radar-maps

# then re-do the two cells Taiwan straddles, with the detail pack on top
# (the 9 MB county file is not in the firmware repo — fetch it into the cache first)
curl -Lo tools/cache/twcounty2010.geojson \
  https://raw.githubusercontent.com/g0v/twgeojson/master/json/twCounty2010.geo.json
python tools/make_tiles.py --out ../flight-radar-maps --cells N20E120,N20E110 \
    --add-geojson tools/cache/twcounty2010.geojson \
    --airspace-geojson tools/taiwan_airspace.geojson --min-airport small
```

A full world run is 1203 tiles and 6.8 MB across the three levels.

Note `--add-geojson`, not `--geojson`: a detail pack is drawn *in addition to* Natural Earth.
A cell is 10° across and usually holds several countries, so replacing the whole outline with
one national boundary file would erase every neighbour's coastline in that cell.
